# VaultNotes

A small Flask + SQLite notes app, **intentionally vulnerable** for security-portfolio purposes.

⚠️ **Run locally only. Do not deploy this publicly** — it contains a working SSRF endpoint and other real vulnerabilities.

## Setup

```bash
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python db.py                       # creates vaultnotes.db + seed users
python app.py                      # runs on http://localhost:5000
```

**Seed accounts** (created by `db.py`, printed to console on init):

- `admin` / `AdminPass123!`
- `alice` / `AlicePass123!`
- `bob` / `BobPass123!`

## What's in here

This app is deliberately built with several vulnerabilities baked into otherwise-normal-looking code — the kind a junior dev might actually ship, not obvious CTF traps. Your job: find them, exploit them, document them, then patch them. Nothing in this repo tells you exactly where they are — that's the point — but here's the general shape of what to look for, organized by the OWASP-flavored categories from the original project spec:

- Authentication and session handling (`auth.py`)
- Authorization on note access (`notes.py`)
- Data rendering in templates (`templates/`)
- The search feature (`models.py`, `notes.py`)
- The link-preview feature (`notes.py`)
- How the admin role gets assigned and checked (`auth.py`, `admin.py`)

A reasonable workflow:

1. Read through the code like a reviewer, but also poke at the running app like an attacker (manually, with curl, and with Burp Suite).
2. Run `bandit -r .` (SAST) and OWASP ZAP against the running app (DAST) — compare what the tools catch vs. what you find manually.
3. For each finding: reproduce it, write it up (description, PoC, severity, root cause, fix), then patch it and re-verify.
